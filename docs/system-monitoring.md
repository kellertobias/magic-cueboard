# Windows system monitoring

Telemetry freshness uses local monotonic elapsed time and the age of the Pi server cache, not differences between Windows and Pi wall clocks. The Windows system status shows Connected only while fresh readings are arriving; otherwise it shows Windows reconnecting or Waiting for Windows data. New browsers request the current telemetry and Windows connection state explicitly. The Windows adapter uses a five-second handshake timeout and ping/pong checks; an unresponsive connection is replaced after roughly 15–20 seconds. Retries back off from one second to ten seconds and reset when Windows reconnects. Restart and stalled-connection recovery are covered by local WebSocket integration tests.

This installation uses the direct Windows–Pi link: Windows `10.99.0.1`, Pi `10.99.0.2`. The default Windows feed is `ws://10.99.0.1:47872/surface`. If the Pi has an existing `.env`, update `WINDOWS_MAGICQ_WS_URL` to that value; environment configuration takes precedence over defaults. The default ToskLight API is also on `10.99.0.1:5000`. GPU and temperature are optional; temperature stays unavailable until a supported monitoring application exposes its sensors through WMI.
